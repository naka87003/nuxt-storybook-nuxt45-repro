# Nuxt 4.5.2 / `@storybook-vue/nuxt` reproduction

This repository reproduces a Storybook preview initialization error when using Nuxt 4.5.2 with the current `@nuxtjs/storybook` PR build.

## Versions

- Nuxt: `4.5.2`
- Storybook: `10.6.1`
- `@nuxtjs/storybook`: `https://pkg.pr.new/nuxt-modules/storybook/@nuxtjs/storybook@2df8f6b`

There is deliberately no custom Vite configuration and no `optimizeDeps` configuration.
`@storybook/vue3` is not a direct dependency; it is installed transitively by
`@storybook-vue/nuxt`.

## Reproduction

```sh
npm install
npm run storybook
```

Open <http://localhost:6006/iframe.html?id=reproduction-button--default&viewMode=story>.

To run the type check:

```sh
npm run typecheck
```

## Actual result

The Storybook preview stays blank. The browser console shows:

```text
Uncaught TypeError: Cannot read properties of undefined (reading 'app')
    at getAppConfig (virtual:nuxt:.../.nuxt/paths.mjs:3:46)
    at baseURL (virtual:nuxt:.../.nuxt/paths.mjs:4:30)
    at virtual:nuxt:.../.nuxt/fetch.mjs:5:14
```

## Why this is minimal

`app/plugins/api.ts` follows Nuxt's documented custom `$fetch` pattern: it creates a custom API client with `$fetch.create()` and provides it to the Nuxt app. This makes Nuxt generate and load its `$fetch` runtime module. No application configuration, third-party Nuxt module, custom Vite setting, or Storybook addon beyond `addon-docs` is involved.

The issue occurs because the preview entry generated by the package imports Nuxt's generated plugins before the Storybook preview has populated `window.__NUXT__`. With Nuxt 4.5.2, evaluating the generated `$fetch` module reads the app configuration immediately.

Removing `app/plugins/api.ts` can hide the error, but does not address the initialization ordering problem.
